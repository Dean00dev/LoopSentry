# LoopSentry v0.2.0-alpha.1 — Evidence Before Enforcement

LoopSentry's second public alpha turns the original six-fixture detector sketch into a provider-neutral, evaluation-led streaming instrument.

## What changed

- Staged `FLAG → TERMINATE_ELIGIBLE` outcomes keep observation separate from caller policy.
- Receipts now report the actual retained repeat run, exact unit span, period, and bounded-window status without reproducing source content.
- Structured model, agent, and tool events can be reduced through a caller-supplied normalization key.
- A new CLI scans characters, words, lines, and canonical JSONL with distinct clear, flag, and termination-eligible exit codes.
- The versioned corpus grows from 6 to 32 synthetic cases: 12 pathological, 16 benign, and 4 deliberately ambiguous.
- Corpus identity is SHA-256 bound, validation is strict, and machine-readable evaluation artifacts are produced in CI.
- The package is tested across Linux, macOS, Windows and Python 3.10–3.14 before distributions are built.
- CI dependencies are pinned to full commit SHAs, and the formerly incomplete license file is replaced with the complete Apache-2.0 text.

## Reproduced corpus result

At the committed detector defaults, all 12 labelled pathological cases are detected, none of the 16 labelled benign cases are flagged, and all four ambiguous cases are surfaced separately. Median pathological detection latency is 32 units; maximum is 128 units.

Those numbers describe this small synthetic corpus only. They are not production false-positive or safety rates.

## Install

```bash
python -m pip install "loopsentry @ git+https://github.com/Dean00dev/LoopSentry.git@v0.2.0-alpha.1"
```

## Upgrade note

The package remains an alpha. `min_observed_tokens` and `observed_tokens` continue to work as aliases, but new code should use the provider-neutral `min_observed_units` and `observed_units` names. Detection no longer implies that callers should immediately cancel a stream; configure and handle `terminate_repeats` explicitly.

See the README, design document, evaluation protocol, threat model, and verification receipt for the complete boundary.
